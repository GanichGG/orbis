## Что это
Сеть (и весь проект) пользователь называет **Orbis**.
Цель к пятнице: **Orbis Epigram** — первая маленькая рабочая модель (v2 поверх w32 + ~1000–1500 реальных разметок, 15–25 кусков).
Программа: видео со стикмен-анимацией (стиль Stick Nodes) → R6-анимация в Blender → Roblox.
Пользователь кликает пипеткой по персонажам, программа размечает суставы нейросетью, спрашивает
только спорные кадры, дообучается на ответах, экспортирует `.r6.json`, импортёр ставит ключи в Blender.

## Конвейер (файлы)
- `stick2r6.py` — главная программа (CLI + окна OpenCV из `ui.py`): пипетка → выделение → сеть → трекинг →
  вопросы (сначала разные позы `--first`, потом спорные) → дообучение каждые N ответов → проверка → экспорт.
- `ui.py` — окна: `pick_colors` (пипетка с живой заливкой), `label_frame` (точки уже расставлены, перетаскивание,
  Q/W меняют руки/ноги, S пропуск, Esc хватит), `review`.
- `stickpose/colorseg.py` — пипетка: цвет персонажа vs палитра фона (k-means в каждом кадре), подстройка под
  цветовые вспышки, одноцветные персонажи делятся по прошлой маске. ~0,4 с/кадр (можно ускорить: палитру раз в N кадров).
- `stickpose/pipeline.py` — маски → кроп 128×128, 2 канала (свой силуэт, чужие силуэты) → модель → пики суставов
  в координатах кадра; толщина линии = масштаб; `finetune()` на разметках.
- `stickpose/model.py` — StickPose (Orbis v2): U-Net, вход 4×128 (свой силуэт, чужие, свой в кадре f−1 и f+1 —
  сеть видит движение), выход 8 карт 64×64: head, neck, hip, hands, feet, elbows, knees (пары по 2 пика) + карта костей.
  Веса v1 (2→5) грузятся и работают; `upgrade()` делает из v1 модель v2 с теми же знаниями (train.py --resume сам).
- **Правило переноса (от пользователя):** голова = голова, торс = таз→шея, **рука R6 = предплечье (локоть→кисть),
  нога R6 = голень (колено→стопа)** — так анимация живее. 11 точек: 7 старых + l/r_elbow, l/r_knee (в конце списка).
  Направление персонажа — по коленям (`postprocess.facing`), без `--facing` берётся само.
- `stickpose/synth.py` — генератор синтетики: позы, стили Stick Nodes, сгибы, перспектива, смаз, шлейфы-призраки,
  наложения других персонажей, частицы, кроп как в реальном конвейере. Сюда добавлять новые стили.
- `stickpose/train.py` — обучение (сам берёт CUDA). `--real dir` подмешивает реальные разметки `*.npz`.
  Каждые 200 шагов пишет в `--out` и состояние оптимизатора: `--resume тот же файл` продолжает с того же шага.
- `stickpose/track2.py` — трекер: Витерби 2-го порядка по всему видео (торс поштучно, руки/ноги парами),
  смены плана (разрыв), нормировка по длине торса, память поз (похожий силуэт), флаги спорных кадров.
- `stickpose/postprocess.py` — фиксация стоп на земле + выбор ключевых кадров (RDP по углам частей, допуск 4°).
- `blender_import_ikrig.py` — **импорт на риг пользователя** (см. ниже). `blender_import_r6.py` — на простой R6-скелет.
- `compare.py` — видео «оригинал с точками | R6 сверху» (`<видео>_compare.mp4`), ключи интерполируются как в Blender.
- `stickpose/evaluate.py`, `overlay.py`, `make_testvideo.py`, `test_e2e2.py`, `tools/test_ik.py` — проверки.
- Старые модули v1 (`vision.py`, `tracker.py`, `segment.py`) удалены; их не возвращать.

## Риг пользователя (basefile.blend) — проверено
Две арматуры: `__PrimaryArmature` (управление) и `InternalArmature` (настоящий R6: HumanoidRootPart, Torso,
Head, Left/Right Arm/Leg; ведомый, напрямую не ключевать). Персонаж смотрит в +Y, Z вверх, левая сторона −X.
- Корень: `MasterControl` (location). Таз = голова кости `Spine`.
- Наклон торса задаёт **`LowerTorso-FK`** (поворот вокруг таза); `Torso_FK` к нему не привязан (CHILD_OF влияние 0).
- Ноги: IK включён (`*LowerLeg` IK → `*Leg-IK`), pole `*Leg-Pole` — дети IK-целей, не трогаем.
  Ноги = «крепление» `*UpperLeg` + «конечность» `*LowerLeg`; R6-нога следует за голенью.
- Руки: **в файле FK** (IK влияние 0) → поворачиваем `LeftArm_FK`/`RightArm_FK`. Скрипт сам определяет режим.
- Голова: FK-кость `Head` (TRACK_TO на `LookToPoint` выключен) → поворачиваем `Head`.
- Контроллеры ставятся через «аффинный решатель» (`solve_locations`): 4 пересчёта сцены дают точное смещение
  с учётом CHILD_OF/COPY_LOCATION.
- `LEG_MODE`: `plant` (стопы в реальных точках, колено гнётся, стопы не скользят) / `straight` (нога по линии таз→стопа).
- `DETACH = 1.0` (этап 1): блок руки/ноги R6 сдвигается костями `*_Positioner` так, что его конец ровно в кисти/стопе
  (таз = низ торса R6, торс стикмена = 2 шпильки). Проверка: 0,00 шп. Этап 2 (план): «разумное расстояние» от плеча/таза.
- `LIMB_RULE` (по умолчанию): руки FK по предплечью; ноги — IK-цель = таз + бедро·u + голень·d, если полюс согнул
  колено не туда — нога прямо по голени + доворот цели. Ключи ставятся с интерполяцией `INTERP` (LINEAR).
- Проверка `python tools/test_ik.py basefile.blend` (синтетика 11 точек, все кадры): торс 0,0°, голова 0,3°,
  руки 0,1°, ноги 0,7° (макс 0,8°). 120 кадров за 3 с.

## Данные и обучение (план «научить определять», 4 этапа)
1. **Mocap** — `tools/fetch_mocap.py` → `weights/mocap.npz` (CMU, 1130 записей, 466 тыс. кадров 30 fps, 43 МБ; не в git).

   (Файлы .stknds не читаются — формат закрыт; sticknodes-rs читает только .nodes-фигуры.)
3. **Самообучение** — `tools/selftrain.py ролики/` → `weights/pseudo/*.npz` (уверенные кадры: трекер уверен,
   плавно, совпадает с зеркальным кадром) → `train.py --pseudo ../weights/pseudo`.
4. **Экзамен** — `tools/exam.py make видео` (пользователь размечает ~30 кадров, эталон, в обучение не идёт),
   `tools/exam.py run веса...` → средняя ошибка углов частей R6 по правилу переноса. **Любое изменение — через экзамен.**

## Грабли
- Не загружать длинное видео целиком в память (929 кадров FullHD убили процесс обучения по OOM) — читать потоком.
- Фоновые задачи в облачном контейнере живут максимум 2 часа — обучение делить на этапы с `--resume`.
- В облачном контейнере сервер pytorch.org заблокирован — ставить `torch` из PyPI. `pip install bpy` (5.2.2) работает для тестов без окна.
- Дообучение на CPU медленное: в программе на CPU шагов меньше и реже (на GPU 300 шагов каждые 4 ответа).
